### 1.2 Plán vs. realita — tři podstatné odchylky

**a) Žádný scraping neexistuje.** V repozitáři není `requests`, `bs4`, `selenium`, `httpx` ani nic podobného.
Data se neberou ze zdrojové stránky, ale z **herních `.txt` souborů D2R** vyextrahovaných CascView
(`index.json` → `excel_dir: "H:\Apps\CascView\Work\D2R 2_7\data\data\global\excel"`).
`rebuild_dataset.py` je TSV→JSON dumper. To je věcně **lepší** než scraping (autoritativní zdroj, žádná
právní ani stabilitní rizika), ale znamená to, že celá "ingestion" větev plánu je jinde, než plán říká —
a že data nejde obnovit bez ruční extrakce z instalace hry.

**b) Interní datový model Item / Skill / Class / Build / Mechanic / Source v kódu neexistuje.**
Existuje devět JSON souborů, z nichž **jen `monsters_base.json` je skutečně normalizovaný**
(vlastní schéma, per-difficulty bloky, typované hodnoty). Zbytek — `skills_raw`, `skilldesc_raw`,
`missiles_raw`, `states_raw`, `pettype_raw`, `itemstatcost_raw` — jsou doslovné dumpy TSV řádků
(429 skillů × **322 sloupců** jako stringy). Normalizace tedy **není hotová ani ze čtvrtiny**;
je hotová pro jednu entitu ze šesti.

**c) Flutter aplikace je navíc oproti plánu** — v plánované architektuře (Python → Java → PG → React/Flutter)
měl klient přijít až po backendu. Existuje, ale nefunguje (viz 1.4).

  → Dart testy se **nezkompilují**.
- ~8 osiřelých souborů nedosažitelných z `main.dart`: `catalog_service.dart`, `catalog_models.dart`,

## 3. Rizika

### 3.1 Technický dluh

| Riziko | Závažnost | Poznámka |
|---|---|---|
| **Necommitnutá práce** | **kritické** | Jediná kopie je na disku. Selhání disku = ztráta projektu. |
| **Repozitář v nespustitelném stavu** | vysoké | Po 6 měsících pauzy je `ImportError` nejhorší možný vstupní bod. |
| `eval()` na řetězci přeloženém z dat | střední | `expr.py` staví Python kód a volá `eval()` s omezenými `__builtins__`. Dnes bezpečné (data z vlastní extrakce), ale **v momentě, kdy to poběží na serveru nad daty od uživatele nebo z modu, je to RCE**. Do Javy se to neportuje — tam bude potřeba skutečný AST interpret (Dart verze ho už má: `tokenizer/parser/eval`). |
| **Empiricky "fitnuté" konstanty** | střední | `_dm_curve` s `K = 5.5`, `_gm_velocity_curve` s `p = 1.09, K = 5.991145572786393`, plus ruční interpolační tabulka pro Clay Golem slow%. Komentáře přiznávají, že jde o fit na pár odečtených tooltipů. **Mimo ověřené body to bude tiše špatně** a nemáš jak to poznat. |
| Duplicitní implementace ve dvou jazycích | střední | Evaluátor existuje v Pythonu (`eval`) i Dartu (AST). Rozjedou se. |
| Golden testy ≠ ověření správnosti | střední | Baseline je vygenerovaný z vlastního výstupu enginu, ne z hry. Chytí regresi, **nechytí systematickou chybu**. Pro RS/RSM je matematika nezávisle ověřená proti `skills.txt`, u Clay Golem ne — a ten nemá testy vůbec. |
| Windows-only cesty | nízké | `"Scripts"` s velkým S, `.\\data\\...` v `baseline.meta.generated_dir`, `H:\Apps\...` v `index.json`. Na Linuxu/CI spadne. |
| Mrtvý kód | nízké | ~8 osiřelých Dart souborů, `BAK_*`, `dump_skilldesc_rs.py` v rootu, `overrides/skills_effects.json` (paralelní deklarativní pokus, nikde se nečte). |

### 3.2 Scope creep

Toto je největší riziko projektu, ne kód.

Za dva commity a ~5 100 řádků má projekt rozestavěné: exportér dat, expression evaluátor,
tři výpočetní modely, Flutter aplikaci pro **6 platforem** (Android, iOS, web, Windows, macOS, Linux),
placeholder pro Baldur's Gate, katalog s pěti vypnutými moduly (runewords, crafting, bestiary, diffs),
plánovanou Java vrstvu, PostgreSQL, uživatelské účty, in-app měnu, reklamy, RAG asistenta.

**Hotový a ověřený je jeden skill.** Poměr rozestavěných front k dokončeným je zhruba 10:1.
Šest měsíců pauzy je typický výsledek — návrat do projektu, kde je deset otevřených front
a žádná zelená, stojí příliš mnoho energie.

### 3.3 Slabá místa datového modelu

1. **Není model postavy/buildu.** Bez něj nejde Fáze 3 a nejde ani správně počítat synergie —
   `overrides_total` / `overrides_base` je náhražka (ruční zadání levelu jiného skillu).
2. **Není model itemu.** `EvalContext.stats = {}`. Iron Golem (v ROADMAP označený jako nejtěžší)
   je bez něj neřešitelný, stejně jako jakýkoli +skills výpočet.
3. **`skills_raw` není datový model, je to CSV v JSONu.** 322 stringových sloupců bez typů.
   Do relační DB to musí projít projekcí, kterou nikdo zatím nenapsal.
4. **Chybí `Source` / provenience.** Neexistuje záznam "tato hodnota pochází z `skills.txt` verze 2.7,
   sloupec `Param3`". Při upgradu D2R nebo přidání módu nepůjde říct, co se změnilo.
5. **Není víc zdrojů, jen jeden.** Pipeline umí přesně jednu složku jedné verze jedné hry.
   `raw_sources/d2r_2_7/` naznačuje verzování, ale nic ho nepoužívá. `data/baldurs_gate/monsters.json`
   má 0 bajtů. Na víc zdrojů **připravená není** — ale rozšířit ji je snadné, protože builders
   v `rebuild_dataset.py` jsou oddělené funkce.

## 5. Python-first (A) vs. Spring Boot slice-first (B)

### 5.1 Kolik práce ten slice reálně je

**Co hraje pro tebe:** `monsters_base.json` je čistě normalizovaný a jde do tabulky téměř 1:1.
`ui_catalog.json` dá taxonomii tříd. A hlavně — **17 baseline případů je hotová akceptační sada**;
Java port má proti čemu měřit správnost od prvního dne. To je nezvykle příznivý start.

**Co hraje proti:** `skills_raw` se 322 sloupci se do schématu nedostane bez projekce (~25 sloupců,
je to designová práce). A `expr.py` se do Javy neportuje 1:1 — `eval()` v Javě není; buď portuješ
Dart AST interpret, nebo pro první slice **jen tvrdě zakóduješ vzorec Raise Skeleton** (což stačí).

| Krok | Odhad (učíš se Spring Boot za pochodu) |
|---|---|
| Skeleton, Docker Compose + PostgreSQL, Flyway, healthcheck | 6–10 h |
| Schéma + migrace (game, skill, skill_param, monster, monster_stat, taxonomy) | 6–10 h |
| Importer generovaných JSON → PG (Jackson, batch insert) | 10–14 h |
| Read API: `/skills` (filtr, stránkování), `/skills/{key}`, `/monsters/{id}` + DTO + `@ControllerAdvice` | 10–14 h |
| Port Raise Skeleton + Skeleton Mastery + `seg5` do Javy, `POST /summons/{key}/compute` | 10–16 h |
| Testy: parametrizovaný JUnit nad 17 baselinami, MockMvc, Testcontainers | 8–12 h |
| springdoc OpenAPI, README, Dockerfile, GitHub Actions | 6–10 h |
| **Celkem plná verze** | **56–86 h ≈ 4–6 týdnů při 15 h/týden** |
| **Osekaná verze** (jedna hra, PG bez Testcontainers, jen RS, bez CI) | **25–35 h ≈ 2 týdny** |

### 5.2 Argumenty pro A (pokračovat Python-first)

- Datový model **ještě není usazený** (chybí Item, Build, Source). API postavené nad nehotovým
  modelem se bude přepisovat.
- Python engine je 90 % hotový k tomu, aby pokryl celý Necromancer strom. Dotáhnout ho
  je nejrychlejší cesta k něčemu, co je *skutečně užitečné pro hráče* — a tím i k monetizaci.
- Pořadí v původním plánu není nesmysl: nejdřív mít správná data a ověřenou matematiku,
  pak je vystavit.
- Nižší riziko rozdělané třetí fronty.

### 5.3 Argumenty pro B (Spring Boot slice první)

- **Pro Java pozici má současný repozitář hodnotu blízkou nule.** Náborář uvidí Python skripty
  a rozbitou Flutter appku. Java tam není ani řádek.
- Slice ukazuje přesně to, na co se u juniorní/mediorní Java pozice ptají: Spring Boot, JPA/JDBC,
  Flyway migrace, REST design, DTO vs. entita, exception handling, JUnit, Testcontainers,
  Docker, OpenAPI. Sedm až osm položek ze zadání typického inzerátu, doložených jedním odkazem.
- **Nejde o "cvičný" projekt** — je nad reálnými, netriviálními daty (429 skillů, 752 monster,
  D2 expression jazyk). To se pozná a je to při pohovoru o čem mluvit.
- Golden testy dělají z portu **měřitelnou** práci: "17/17 shodných výsledků s referenční
  Python implementací" je věta do README, kterou většina portfolio projektů nemá.
- Nemusí to být slepá ulička. Slice je zároveň Fáze 1 (DB + API) z původního plánu —
  jen postavená v jazyce, který chceš profesně.

### 5.4 Doporučení

**Jdi variantou B, ale v osekaném rozsahu a až po P0.**

Konkrétně:

1. **P0 stabilizace (3–5 h).** Nejde přeskočit. Java importer bude číst ty JSONy a Java compute
   se bude měřit proti těm baselinám — musí být obojí v ověřitelném, commitnutém stavu.
   Rozbitý Python repozitář je špatný vstup i špatná vizitka.
2. **Slice s tvrdě daným rozsahem:** jedna hra, jedna varianta, `GET /api/skills` s filtrem podle
   třídy a fulltextem v názvu, `GET /api/skills/{key}`, `GET /api/monsters/{id}`,
   `POST /api/summons/raise-skeleton/compute`. **Nic víc.** Žádné účty, žádný build planner,
   žádný druhý summon, dokud tohle neběží nasazené.
3. **Akceptační kritérium:** `docker compose up` → API běží, Swagger UI na `/swagger-ui`,
   `mvn test` zelený včetně 8 RS baseline případů. Nasazeno na Render/Fly.io/Railway free tier.
   Odkaz do CV.
4. **Až potom** se vrať k Pythonu a doplň zbylé summony — a nech Python natrvalo v roli
   offline ingestion nástroje, tak jak to původní plán zamýšlel. Python zůstává generátorem
   `data/**/generated/*.json`, Java je jediný runtime. Tím se zbavíš i duplicity evaluátoru.

**Co tím obětuješ:** ~2 týdny, které by jinak přidaly 3–4 summony do Python enginu.
**Co za to dostaneš:** nasaditelný Java artefakt s testy a dokumentací — jediná věc v tomhle
projektu, která přímo posouvá cíl "Java Developer pozice". Summony počkají; ony neutečou.
